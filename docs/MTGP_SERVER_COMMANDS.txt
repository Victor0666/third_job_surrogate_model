四、正式训练公共参数（每个新终端先执行本节，再执行第五节）
默认：Single 协议、Tight（T）、算法随机种子 0、8 个 CPU 进程。
9 情景：SS、SM、SL、MS、MM、ML、LS、LM、LL；第一位是任务规模，第二位是资源规模。
严格沿用现有 Single 协议：只训练 SS、SM、SL 三个源模型，覆盖全部 9 个评测情景。
SS 模型评测 SS/MS/LS；SM 模型评测 SM/MM/LM；SL 模型评测 SL/ML/LL。
现有 Single 不允许 MS/MM/ML/LS/LM/LL 作为训练源，不提供会报错的训练命令。
若研究目标是 9 情景各自独立训练，则需要另行明确训练协议，所有方法保持相同训练范围。
种群 1000、51 代、10 个精英；训练环境种子 1-5、验证 101-103、最终测试 201-230。
每回合 50 个工作流。训练结束后自动选择规则并执行最终评测，无需另写评测命令。

这些命令显式使用 scenario_registry 的正式默认 exact_mix_v1 DDL 缓存。
比较方法必须使用同一组缓存。如果你的 LLM-safe-HRL 实验显式使用了 diagnostic
目录下的 fcfs_fixed_XX_exactmix_formal38.json，请将下面所有对应路径一并替换成
那组缓存；不能只为 MTGP 更换缓存，也不要在训练中途重新生成或替换缓存。

DDL=T
ALG_SEED=0
WORKERS=8
CACHES=(
  --deadline-cache SS=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_smallRes_exactmix_formal38.json
  --deadline-cache SM=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_medRes_exactmix_formal38.json
  --deadline-cache SL=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_largeRes_exactmix_formal38.json
  --deadline-cache MS=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_smallRes_exactmix_formal38.json
  --deadline-cache MM=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_medRes_exactmix_formal38.json
  --deadline-cache ML=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_largeRes_exactmix_formal38.json
  --deadline-cache LS=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_smallRes_exactmix_formal38.json
  --deadline-cache LM=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_medRes_exactmix_formal38.json
  --deadline-cache LL=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_largeRes_exactmix_formal38.json
)

五、覆盖 9 个情景的三个源模型训练命令
以下命令默认依次运行；每个模型训练后自动评测对应的三个情景。

# SS
python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario SS --ddl "$DDL" --algorithm-seed "$ALG_SEED" --workers "$WORKERS" --threads-per-worker 1 "${CACHES[@]}"

# SM
python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario SM --ddl "$DDL" --algorithm-seed "$ALG_SEED" --workers "$WORKERS" --threads-per-worker 1 "${CACHES[@]}"

# SL
python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario SL --ddl "$DDL" --algorithm-seed "$ALG_SEED" --workers "$WORKERS" --threads-per-worker 1 "${CACHES[@]}"

六、可选：用循环依次训练并覆盖 9 情景（与第五节任选一种，不要重复执行）

for SCENARIO in SS SM SL; do
  python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario "$SCENARIO" --ddl "$DDL" --algorithm-seed "$ALG_SEED" --workers "$WORKERS" --threads-per-worker 1 "${CACHES[@]}" || break
done

如需另外两种 DDL，先改 DDL=M 或 DDL=L，再运行第五节或第六节。
3 个源模型 x 3 种 DDL = 9 次独立训练，覆盖 9 情景 x 3 种 DDL 的 27 组评测。
这与 Multi 协议不同；Multi 在同资源规模的三个任务情景上联合训练。
如需多个算法种子，分别设置 ALG_SEED=0、1、2 等，每个种子独立训练。

七、断点恢复（以 SS 为例，其他情景替换 --scenario 即可）
先执行第四节，保持原来的 DDL、ALG_SEED、缓存及输出目录，然后追加 --resume。
WORKERS 可以改变。每代保存一次，中断时未完成的那一代会重新计算。
源代码、输入文件、Python/NumPy 版本变化会拒绝恢复；不要直接迁移 Windows 断点到 Linux。
规则已选好时，--resume 只重跑冻结最终评测，不重新演化。

python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario SS --ddl "$DDL" --algorithm-seed "$ALG_SEED" --workers "$WORKERS" --threads-per-worker 1 "${CACHES[@]}" --resume

八、输出位置与公平性
默认输出：out/comparisons/mtgp/transport_v1/single/<情景>/<DDL>_a<算法种子>/
例如：out/comparisons/mtgp/transport_v1/single/SS/T_a0/
training_checkpoint.json：每代断点；rules.json：验证集选中的两棵树；
history.json：逐代训练记录；eval.json / eval.csv：冻结最终评测结果。
正式评测保持串行；训练和验证使用 CPU 多进程。无需 GPU。
所有方法共享当前阶段式通信模型与生产评测函数；旧通信模型结果不能混入新主实验。
