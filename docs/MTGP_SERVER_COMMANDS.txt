四、9 个任务的定义与运行方式
SS、SM、SL x T、M、L = 9 个独立训练任务；默认算法种子 0。
SS 模型评测 SS/MS/LS；SM 模型评测 SM/MM/LM；SL 模型评测 SL/ML/LL。
Single 协议、两棵树协作方式、共享评测函数及训练/验证/测试种子保持不变。
种群 1000、51 代、10 个精英；训练种子 1-5、验证 101-103、最终测试 201-230。
每回合 50 个工作流，训练后自动验证选模并执行最终评测。

每条命令均完整展开参数，不需要设置 DDL、ALG_SEED、WORKERS 或 CACHES 变量。
在每个终端进入项目根目录并激活环境，然后复制对应的一条命令。
可分配到不同终端或不同服务器运行；不要在同一共享输出目录重复启动同一个任务。
默认每个任务 --workers 4 --threads-per-worker 1。9 个同时启动是 36 个工作进程，
另有主进程；请按服务器 CPU 和内存调整 --workers 或同时运行的任务数量。
如果希望保留原来的每任务 8 进程，将对应命令中的 --workers 4 改为 --workers 8。
Worker 数量可以改变，算法随机数、训练范围及评测逻辑不变。

六、断点恢复
找到对应的原始命令，保持 scenario、DDL、算法种子、缓存及输出目录，末尾追加 --resume。
已启动的 SS 训练继续正常运行即可，不要为了新命令停止它或同时启动另一个 SS_T。
若 SS 原命令是算法种子 0、T 和上述缓存，下面可以恢复同一默认输出目录：

python -m algorithms.comparisons.mtgp.run_pipeline --protocol single --scenario SS --ddl T --algorithm-seed 0 --workers 4 --threads-per-worker 1 --deadline-cache SS=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_smallRes_exactmix_formal38.json --deadline-cache SM=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_medRes_exactmix_formal38.json --deadline-cache SL=data/deadlines/fcfs/exact_mix_v1/fcfs_smallTask_largeRes_exactmix_formal38.json --deadline-cache MS=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_smallRes_exactmix_formal38.json --deadline-cache MM=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_medRes_exactmix_formal38.json --deadline-cache ML=data/deadlines/fcfs/exact_mix_v1/fcfs_medTask_largeRes_exactmix_formal38.json --deadline-cache LS=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_smallRes_exactmix_formal38.json --deadline-cache LM=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_medRes_exactmix_formal38.json --deadline-cache LL=data/deadlines/fcfs/exact_mix_v1/fcfs_largeTask_largeRes_exactmix_formal38.json --resume

每代保存一次，中断时未完成的那一代会重算。
源代码、输入文件和 Python/NumPy 版本变化会拒绝恢复；不要直接迁移 Windows 断点到 Linux。
规则已选好时，--resume 只重复最终评测。
不同服务器首次开始训练可以使用其原环境；本地测试环境为 Python 3.12，
当前服务器为 Python 3.11，恢复训练时请保持该服务器自己的运行版本。

七、输出与日志解释
9 个任务的默认目录相互独立，分别为：
out/comparisons/mtgp/transport_v1/single/{SS,SM,SL}/{T,M,L}_a0/
training_checkpoint.json：每代断点；rules.json：验证集选中的两棵树；
history.json：逐代训练记录；eval.json / eval.csv：最终评测结果。
日志四元组依次为：DDL 违约率、最大模糊迟到量、平均模糊迟到量、模糊能耗评分。
按上述顺序最小化；simulated 为当代实际新评估数，cache_hits 为缓存复用数。
每代轮换训练种子 1-5，日志是当代最佳训练结果，不是最终测试结果。
正式评测在单个任务内部串行；多个任务同时运行时，运行耗时会受 CPU 争用影响。
如果论文要比较调度耗时，训练完成后应在空闲服务器上逐个用原命令加 --resume 重评测。
旧通信模型的指标不能混入当前阶段式通信模型的主实验。

未在目标 Linux 服务器启动这 9 个完整训练，也未重新安装其现有 Python 环境。
